# 本机运行环境（不打开云电脑也能跑工具链）

> 目的：这套工具原来把模拟器路径写死成 `D:/miliastra-beyond-simulator`，**只有云电脑能跑**。
> 现在 21 个工具统一走 [tools/sim-root.mjs](../tools/sim-root.mjs)，
> 在任何一台装了 Node 的机器上都能跑逻辑测试 / 出图 / 静态检查 / 存档透视。

## 一、模拟器找的顺序

1. 环境变量 `XUEHUANG_SIM=<模拟器根目录>`
2. 仓内 `third_party/beyond-sim`（已 gitignore）
3. `D:/miliastra-beyond-simulator`（云电脑原位置，行为不变）
4. 仓的上一级目录下的 `miliastra-beyond-simulator`

判据是 `<根>/client/lua-runtime/src/index.js` 存在。找不到时多数工具**跳过而不是报错**。

## 二、在没有云电脑的机器上怎么放运行时（以 Android/Termux 为例）

运行时是社区项目 [1475505/miliastra-beyond-simulator](https://github.com/1475505/miliastra-beyond-simulator)（千星沙箱模拟器），
仓库根 `client/lua-runtime` 只需要 15 个文件：

```
third_party/beyond-sim/client/lua-runtime/{src/*.js, package.json}
third_party/beyond-sim/client/lua-runtime/node_modules/fengari/       # 唯一依赖，npm 上 0.1.5
```

⚠️ 两个坑（都是实测）：
- **GitHub 443 在部分网络下不通**（`git clone` / `https://github.com` 都会失败）：
  可用 `git clone git@github.com:...`（SSH），或用 jsDelivr 逐文件取：
  `https://cdn.jsdelivr.net/gh/1475505/miliastra-beyond-simulator@master/<路径>`，
  目录树用 `https://data.jsdelivr.com/v1/packages/gh/1475505/miliastra-beyond-simulator@master`。
- **`@napi-rs/canvas` 的原生 `.node` 不能放在 `/sdcard`**（共享存储是 noexec，
  dlopen 报 `library ... is not accessible for the namespace`）。出图类工具要用 canvas 时，
  把它装在**应用自有文件系统**（Termux 的 `$HOME`/`$PREFIX`，或 `$TMPDIR`）里。

## 三、这台机器上验证过什么（2026-10-01，Android 14 / Termux / Node 26）

| 项目 | 结果 |
|---|---|
| `node tools/lua-compile.mjs` | 23 个 Lua 文件全部编译通过 |
| `logic / kitchen / game / restore` | 29 / 39 / 12 / 31 全过 |
| `node tools/ui-oracle.mjs` | passed 5 / failed 0（表现层与逻辑层判据一致） |
| `node tools/layout-lint.mjs` | 能跑；它是拿 **dist 里的产物** 量的，不是源码 |
| `node tools/gil-inspect.mjs 临时.gil` | 能读出"关卡里存的是哪一版脚本" |
| `node tools/view-snap2.mjs` | 能出 1280×720 PNG（读得到 132 个可见控件） |

## 四、这台机器做不了的三件事（必须回云电脑）

1. 编辑器里**重新导入脚本 + 保存关卡 + 进游戏**；
2. 读 `Beyond_Debug_Log/*.gia`（在云电脑 C 盘；拷到本机也能读）；
3. 真机截图验收（独占全屏）。
