雪皇的后厨 · 火：DOOM 火焰算法（格子版）

移植自 GitHub filipedeschamps/doom-fire-algorithm（1417★，JS）。核心只有三行： 底部一排点火 → 每帧把热量随机地往上传播并衰减 → 每个格子按热量取一个纯色。
因为传播是随机的，火舌会自己扭动、自己收尖 —— 不需要渐变（这正是千星能做的：一堆方块 + 逐格改颜色）。

240 × 200 像素 · 每格 4px（= 120 列 × 50 行）
左边这团是真在烧（浏览器打开看）
调色板： 冷（黑）→ 暗红 → 红 → 橙 → 黄 → 白（最热）

算法就这么多（可直接照抄）

① 建一张 W×H 的热量表，最下面一行固定为最大值（火源）。

② 每帧从下往上扫，对每个格子：随机衰减 rand(0..decay) 后，把热量写到下方偏左/偏右一格（随机方向）—— 这就是"火往上窜"。

③ 按热量值查调色板得到颜色。

为什么它比"画丝带"更适合我们：
它只用纯色格子就出了"扭动 + 收尖 + 渐隐"全部效果 —— 而千星刚好只有方块和图元， 没有渐变、没有曲线笔刷。这个算法和平台约束是同构的。

千星里怎么落：把"格子"换成"方块控件"

网页版（算法原型）千星版（客户端 Lua）
二维热量表 W×H同样一张 Lua 表；建议 24 列 × 14 行（= 336 个格子，控件预算够）
像素/div 格子每格一个 100001 方块控件（建一次进池，运行期只改颜色/位置）
调色板取色同一张调色板（Lua 表），用 SetColor（带 A 通道做"火梢淡掉"）
每帧 requestAnimationFrameOnUpdate(dt) 每帧跑同一步；或按 30fps 节流（火不需要 60fps）
随机衰减 Math.random()不能用 math.random（沙箱会拦）→ 用一个自带的 LCG 伪随机（自备种子，还能保证可复现）

控件预算账（这是唯一要小心的）

24×14 = 336 个方块。平台是每组上限 1000 个控件，我们现有 UI 已经用了 ~250（工位卡/面板/HUD）。 336 + 250 ≈ 590，还有余量，但也就只够一个"大火舞台"。

⇒ 建议：只有"正在做的那个工位"才点火（一份 336 格的火池，四个工位轮流用）， 而不是四个工位各烧一团。这样预算恒定、也不会四个工位一起烧得眼花。
